### What is network interception, why do we need it?
When an app in the browser needs data, it sends an HTTP request (eg "give me the list of promotions") to a backend server and waits for an HTTP response (the data, as JSON usually)

In automated testing, we usually `dont want to call the real backend` because:
- The real backend might be slow, unavailable
- We want 100% preidictable, repeatable test data (not "whatever is in database today')
- We want to test edge cases easily (errors, empty lists, slow responses) without needing the real server to actually produce them.

Network interception means: Playwright sits in between the browser and the real network, like a phone operator who can intercept the call before it reaches the kitchen and either:
- answer it themselves with a prepared answer (`fulfill`)
- hang up on it (`abort`) // Kills the request - the app sees it as a network failure (useful for testing error states, timeouts, offline behaviour)
- or let it ring through to someone else (`fallback`/ `continue`) // "Not my request" - passes control to the previously registered handler for this same pattern(if any), or to the real network if none are left.
- `continue()` // lets the request go to the real network, optionally after modifying it (eg changing headers). 

KeyIdea - `mockApi.intecept()` is a convinence wrapper that configures Playwright to "answer the phone" for a specifc kind of request, with fake data you control.

### 2. HTTP requests and response - the basics
Every network call the browser makes is a `HTTP request` , and the server sends back an `HTTP Response`. Both have a similar shape.

In the code, `route.request()` gives you access to the request object ( so you can inspect its method, URL, headers, body etc). `route.fulfill({...})` lets you construct the entire instead of a real server.

### 3. HTTP methods (GET , POST etc)
The HTTP method (sometimes called 'verb') tells the server what kind of operation the client wants to perform: Eg GET (give me data), POST (create something new eg submit a new comment), PUT/PATCH (update existing data), DELETE (remove data)
Crucially, `the same URL can be called with different methods for different purposes`. For example
- GET /api/promotionLMComment -> fetch existing comments
- POST /api/promotionLMComment -> submit a new comment.
This is exactly why the `method` parameter exisits in `mockApi.intercept()` - so you can mock the same URL differently depending on whether its being read from or written to.

## 4. What a URL "pattern" / glob actually makes
The first argument to `intercept(pattern, ...)` is not necessarily an exact URL - its usually a `glob pattern` a simplified wildcard syntax:

| Pattern<br>                       | Matches                                                                     |
| --------------------------------- | --------------------------------------------------------------------------- |
| `**/api/promotions`               | Any URL ending with `/api/promotions`, regardless of domain/protocol/prefix |
| `*.png`                           | Any path ending in `.png`                                                   |
| `https://api.example,com/users/*` | Any single path segment after `/users/`                                     |
In the codebase, patterns ususally come from a shared constants file eg `API_ROUTES` in tesco framework so the same URL pattern is reused consistenly across tests instead of being harcoded as a raw string each time.

## Playwright's `page.route()` - the interception mechanism
`page.route(pattern, handler)` is the core playwright API . It says 'For any network request this page makes whose URL matches `pattern` , call my `handler` function instead of letting it go straight to the netwrok'. The `handler` function receives a `route` object representing ==one specific intercepted request==. Inside the handler you must call exactly one of: `route.fulfill() , route.abort(), route.fallback(), route.continue()` - this tells playwright what to actually do with the request
Eg
```Typescript title="example.test.ts"
await page.route('**/api/promotion', (route)=> {
	// 'route' represents the specific intercepted request.
	// we decide what happens to it here.
	return route.fulfill({
		status: 200,
		json: [{id:1, name: 'Example Promo'}],
	});
}):
```


### 7. Handler registration order - "last registered, runs first"
If you register multiple `page.route()` handlers matching the same URL pattern, Playwright doesnt run them in the order you wrote them - it runs them in reverse order: the most recently registered handler gets the first crack at the request.

If the hanlder calls `route.fallback()`. Playwright moves to the _the next older handler_ and gives it a turn.
Eg
```Typescript title="example.test.ts"
// Handler A - registered FIRST (generic fallback)
await mockApi.intercept('**/api/promotionLM', []);

// Handler B - registered SECOND (GET-specific )
await mockApi.intercept('**/api/promotionLM', [], GET);

// Handler C - registered THIRD (POST-specific)
await mockApi.intercept('**/api/promotionLM', [] , POST);
```
Execution order when request arrives: C runs first then B then A 

### Javascript Truthy and Falsy
In Javascript, every value is either "truthy" or "falsy" when used in a boolean context like `if(value)`

| Falsy values                                       | Truthy values                                                                                |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `undefined, null, 0, '',(empty string), false,NaN` | Any non-empty string, any non-zero number, any object, any array -basically everything else. |
