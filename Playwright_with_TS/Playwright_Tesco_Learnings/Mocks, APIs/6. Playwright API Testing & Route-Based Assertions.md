## The 2 very different meanings of 'Api testing'

| Classic API testing                                                                                       | Browser-level "API testing" (What we do with Playwright here)                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| You directly call an endpoint yourself  (eg with Postman , curl) and assert on the real server's response | You run the real app in a browser and intercept the network calls it makes, asserting on what the app sent (URL, method, query params, body) and controlling what it receives back (via a fake response) |
| Tests the backend/API contract in isolation                                                               | Tests that the frontend is calling the right endpoint, with the right parameters, at the right time - and renders correctly given a known response.                                                      |
 Key point : In a Playwright test, `page.route()` isnt just a response-faking tool. The handler also receives the full outgoing `request` object, so it doubles as an **assertion point** - you can verify the app is constructing its API calls correctly, before deciding what fake data to hand back

---

## The request object - what you can inspect

Inside a `page.route(pattern, (route) => {...})` handler,`route.request()` gives you  the full outgoing request:

| Method                   | Returns                          | Example                                  |
| ------------------------ | -------------------------------- | ---------------------------------------- |
| `request.url()`          | Full URL string                  | `https://api.x.com/search?q=milk&page=2` |
| `request.method()`       | HTTP verb                        | `GET`, `POST`                            |
| `request.headers()`      | Object of request headers        | `{authorization: 'Bearer xyz` }          |
| `request.postData()`     | Raw request body (string)        | `'{"name": "milk"}'`                     |
| `request.postDataJSON()` | Parsed JSON body (if applicable) | `{name: 'milk}`                          |
Query Parameter arent given to you directly - you extract them from the URL yourself.
```Typescript title="example.test.ts"
const query = new URL(route.request().url()).searchParams;

query.get('offerId'); // -> '1111111'
```

 ---

## Simple generic example - asserting a GET query param

```Typescript title="example.test.ts"
// Imagine the app fires: GET /api/search?term=milk&page=2

await page.route('**/api/search**', (route) => {
	const query = new URL (route.request().url()).searchParams;
	
	expect(query.get('term')).toBe('milk');
	expect(query.get('page')).toBe('2');
	
	return route.fulfill({
		status: 200,
		json: [{id:1, name:'Milk 2L'}],
		
	});
});

await page.goto('/products');
await page.getByPlaceholder('Search').fill('milk');
await page.getByRole('button', {name: 'Search'}).click();
```

## Simple generic example - asserting a POST body
```Typescript title="example.test.ts"
// Imagine the app fires: POST /api/comments body:{text: 'Nice!', userId:42}
await page.route('**/api/comments', (route) => {
	const body = route.request().postDataJSON();
	
	expect(body.text).toBe('Nice');
	expect(body.userId).toBe(42);
	
	return route.fulfill( {status:201, json:{ id:99, ...body} });
});

await page.getByLabel('Comment').fill('Nice!');
await page.getByRole('button', {name: 'Post'}).click();
```

## Note
 ```Typescript
 page.route(pattern, (route)=>{
	 route.request(); // returns 'request' object
 });
 
 const requestPromise = page.waitForRequest(pattern); // returns request<promise>
 const request =  await requestPromise; // returns 'request' object
 ```

### Cheat sheet

| Need to check...                             | Use                                                              |
| -------------------------------------------- | ---------------------------------------------------------------- |
| Was the right URL/path called?               | `request.url()`                                                  |
| Was it GET vs POST vs etc                    | `request.method()`                                               |
| Were the right qurty params sent?            | `new URL(request.url()).searchParams.get('key')`                 |
| Was the right body sent (POST/PUT)?          | `request.postDataJSON()`                                         |
| Were the right headers sent (eg auth token)? | `request.heders()['authorization']`                              |
| Want assertion + mock in one place?          | Pattern A - assert inline inside `page.route()`                  |
| Want guaranteed-clear failure messages ?     | Pattern B - `page.waitForRequest()` + assert outside the handler |
Bottom line - `page.route()` isnt only a response-mocking tool - because it hands you the real outgoing `request` object before you decide what to respond with. it naturally doubles as a way to test that the frontend is making the correct API calls, which is a distinct valuable kind of 'API testing' from a UI test.
