```
Step1: Test starts
Step2: Phase 1 : Setup (happens synchronously)
	beforeEach() runs your mockApi.intercept() calls
	// Result -> a fixed, ordered list of handlers is built for each URL pattern
Step3: Phase 2 : Runtime
	page.goto() runs - the real app fires requests
	// Each request independently walks the already-built list (newest handler first)
Step4 : Response returned to app
```

## Phase 1 (Setup) - how the handler list get built

Each call to `mockApi.intecept(pattern, data, method?)` pushes a new handler onto the top of the list for that URL pattern. 
```Typescript title="example.test.ts"
await mockApi.intercept('**/promotions/v2', dataA);  //call 1
await mockApi.intercept('**/promotions/v2', dataB, 'GET');  //call 2
```

Resulting stack for URL '**/promotion/v2':
```Text
Call 2 (Newest) --> Call 1 (Oldest)
```

## Phase 2(Runtime) - The Generic Per-Request Flowchart
This is what happens 'every single time' the app fires a request matching a registered URL pattern - whether its 1st request or 50th.
```Text
App  fires a request eg GET /**promotions/v2 --> Does the URL match a registered pattern? --> Start at the TOP of the stack(newest handler)
If Yes : 
	route.fallback() // move to the next handler down the stack
If No :
	route.fulfill(data) // response sent to app chain stop here
```
